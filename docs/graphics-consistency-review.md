# 그래픽 일관성 리뷰

> 작성일: 2026-06-03
> 목적: "디자인이 안 예쁘고 화면마다 따로 논다"는 문제의 원인을 도트(픽셀아트) 게임 기준으로 진단하고, 개선 우선순위를 정리한다.
> 방법: 디버그 진입 기능(`?scene=...`)으로 각 씬을 직접 띄워 스크린샷을 찍고 비교.

## 검토한 화면

| #   | 화면                              | 진입 방법               |
| --- | --------------------------------- | ----------------------- |
| 1   | 시작/메뉴 (MenuScene)             | `?scene=menu`           |
| 2   | 게임플레이 1스테이지 (FirstScene) | `?scene=first`          |
| 3   | 보스전 (BossScene)                | `?scene=boss&items=max` |
| 4   | 게임오버 (GameOverScene)          | `?scene=GameOverScene`  |
| 5   | 엔딩 (GameClearScene)             | `?scene=GameClearScene` |

---

## 핵심 진단: "픽셀 격자"가 하나로 통일되어 있지 않다 (가장 큰 원인)

도트 게임은 **모든 그래픽이 동일한 크기의 픽셀(도트) 격자 위에 놓이는 것**이 정의다. 현재 게임은 두 종류의 그래픽이 섞여 있다.

- **배경** (구름, 풀, 동굴, 엔딩 배경): 고해상도의 매끈한 그림. 그라데이션이 부드럽고 도트가 보이지 않는다.
- **캐릭터** (꼬꼬, 돼지, 보스): 저해상도의 굵은 도트 스프라이트.

이 둘이 한 화면에 공존하기 때문에 "스티커를 붙여놓은" 느낌이 나고, 같은 게임처럼 보이지 않는다. 1스테이지에서 특히 두드러진다(매끈한 구름 vs 도트 돼지).

### 기술적 원인

- [src/main.js](../src/main.js) — 게임을 **브라우저 풀 해상도**(`width: window.innerWidth`, `height: window.innerHeight`)로 렌더링한다. 진짜 도트 게임은 **작은 가상 해상도**(예: 480×270)로 그린 뒤 통째로 확대(integer scaling)한다. 그래야 배경이든 캐릭터든 동일한 굵기의 도트가 되어 자동으로 통일감이 생긴다.
- `pixelArt: true`는 켜져 있지만, 이는 "텍스처를 확대할 때 안 흐리게 하는" 옵션일 뿐이다. **이미 고해상도로 그려진 배경 그림 자체를 도트로 만들어주지는 않는다.**
- [src/main.js](../src/main.js)의 `roundPixel: false`는 **오타**다. 올바른 키는 `roundPixels`(끝에 s). 현재 설정값이 무시되고 있다.

> 이 항목은 게임 전체 룩을 바꾸는 큰 작업이라(좌표/크기 보정 수반) 별도 설계가 필요하다.

## 그 외 일관성 문제

### 1. 폰트가 화면마다 다름

- 메뉴 · HUD · 게임오버는 픽셀 폰트를 쓴다.
- **엔딩 스토리 텍스트만 Arial(일반 고딕)** — [src/scenes/GameClearScene.js](../src/scenes/GameClearScene.js)의 `font: "32px Arial"`. 도트 화면에 매끈한 고딕이 끼어 가장 크게 깨진다.
- 또한 픽셀 폰트가 두 종류 혼용된다: TTF `"pixel"`(GAME OVER 제목)과 비트맵 `"pixelfont"`(점수/안내).
- **개선**: 엔딩을 `pixelfont`로 교체. 가능하면 전 화면에서 폰트 1~2종으로 통일. (작업량 적음)

### 2. 화면마다 색 세계관이 따로 놈

- 메뉴 = 쨍한 만화풍, 1스테이지 = 시원한 파랑/초록, 보스 = 갈색 동굴, 게임오버 = 칙칙한 평면 초록, 엔딩 = 파스텔 핑크.
- 공유하는 **공통 팔레트**가 없어 화면 전환 시 다른 게임처럼 느껴진다.
- **개선**: 16~32색 수준의 고정 팔레트를 정하고 전 화면이 공유하도록 한다.

### 3. 스프라이트 외곽선 처리가 제각각

- 보스 황금돼지(`public/assets/monsters/gold-pig.png`)에는 **흰색 외곽선이 이미지에 직접 박혀 있다.**
- 일반 돼지(`public/assets/monsters/pig.png`)와 꼬꼬는 외곽선이 없다.
- 그래서 보스만 "오려 붙인" 느낌이 난다. 코드 쪽에는 보스에 글로우/외곽선 효과가 없으므로(GoldPig는 `gold_pig` 텍스처를 10배 확대만 함), 이 테두리는 100% 에셋에 박힌 것이다.
- **개선 방향(택1)**:
    - A. 보스 PNG에서 흰 외곽선 제거 (에셋 수정 — 도트 에디터 또는 스크립트 자동 처리)
    - B. 꼬꼬·일반돼지에도 외곽선을 코드(`preFX`)로 추가해 통일 (에셋 무수정, 단 번짐 우려)
    - C. 일반 돼지·꼬꼬 PNG에 흰 외곽선을 추가해 보스에 맞춤 (에셋 수정, 반대 방향)
    - 도트 게임에서는 보통 **1px 외곽선이 전부 있는 쪽(C)** 이 또렷하다. 단 흰색이 몸통 내부에도 쓰였으면 자동 처리가 오작동할 수 있어 한 프레임으로 먼저 테스트 필요.

### 4. UI(HUD)가 화면마다 다른 스타일로 짜깁기됨

- 보스 체력바: 손그림풍 둥근 핑크 바.
- 볼륨 슬라이더: 평범한 주황 막대.
- 우측 하단 스탯(이동속도/발사속도/알크기/대미지): 글씨가 작고 대비가 낮아 잘 안 보이고 지저분함.
- 하트·점수: 픽셀 폰트.
- 각자 다른 비주얼 언어를 쓴다.
- **개선**: 공통 "패널 프레임" 한 종류를 정해 전 UI를 거기에 맞춘다. 우측 하단 스탯은 정리/대비 강화.

### 5. 게임오버 화면 구성이 미완성처럼 보임

- 흰색 박스 위에 검은색 박스를 겹치고, "GAME / OVER" 글자가 두 박스의 경계에 걸쳐 어수선하다.
- 배경이 회색 틴트된 또 다른 그림체라 게임 본편과 붙지 않는다.
- **개선**: 레이아웃 정리, 배경/프레임을 본편 톤과 맞춤.

### 6. 엔딩 화면 — 확인 필요 항목

- 제목이 **"ENDER"** 로 보인다(ENDING 오타 가능성). 이는 `ending` **배경 이미지에 박힌 글자**이므로 `public/assets`의 이미지 파일을 수정해야 한다.
- 메뉴 화면 하단의 **"GROW"** 글자도 배경 이미지에 박힌 워터마크/잔재로 보인다. 의도한 것이 아니면 제거.

## 개선 우선순위 (효과 큰 순서)

| 순위 | 할 일                                              | 에셋 수정 | 효과                |
| ---- | -------------------------------------------------- | --------- | ------------------- |
| 1    | 엔딩 Arial → 픽셀 폰트 교체                        | 무        | 즉시, 작업량 적음   |
| 2    | 공통 팔레트 + 공통 UI 패널 정하고 전 화면 적용     | 일부      | 화면 전환 시 통일감 |
| 3    | 게임오버 레이아웃 정리, "ENDER"/"GROW" 이미지 수정 | 유        | 마무리              |

- 보류 :
    - 보스 외곽선 통일(제거 또는 전 스프라이트 추가 - 에셋 수정이라 작업 부담 큼)
    - 가상 해상도 도입(실험 결과 실질 효과 없음)
