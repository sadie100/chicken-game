# 가상 해상도 도입 설계

> 작성일: 2026-06-03
> 근거: [docs/graphics-consistency-review.md](../../graphics-consistency-review.md) 우선순위 #1
> 범위: **가상 해상도 도입(#1)만**. 폰트 통일(#2)·팔레트/UI 패널(#3)·게임오버/엔딩 이미지(#4)·보스 외곽선은 이번 범위 밖.

## 1. 문제와 목표

도트 게임의 정의는 **모든 그래픽이 동일한 크기의 픽셀(도트) 격자 위에 놓이는 것**이다. 현재 게임은 그렇지 않다.

진짜 원인(코드 확인 결과):

- 배경은 576×324 원본을 [Background.js](../../../src/backgrounds/Background.js)가 `height/sourceHeight` 배율로 늘려 그린다.
- 캐릭터는 `setScale(3)`, 보스는 `setScale(10)` 등 **제각각의 배율**로 그려진다.
- 게임은 **브라우저 풀 해상도**(`window.innerWidth/Height`)로 렌더되므로 위 배율들이 화면마다 다른 도트 크기를 만든다.

즉 "고해상도 vs 저해상도"가 아니라 **도트 한 칸의 크기가 그래픽마다 다른 것**이 문제다.

**목표:** 작은 고정 가상 해상도(480×270)로 전체 화면을 렌더한 뒤 통째로 확대한다. 모든 그래픽이 "소스 픽셀 1칸 = 가상 픽셀 1칸"으로 떨어지도록 배율을 정리해, 배경·캐릭터·보스의 도트 크기를 통일한다.

## 2. 확정된 결정

| 항목 | 결정 | 비고 |
| --- | --- | --- |
| 가상 해상도 | **480×270** (16:9) | 배경 원본 576×324에 근접, 도트 굵기 적당 |
| 화면 비율 | **16:9 고정 + 레터박스** | `Scale.FIT` + `CENTER_BOTH` 유지, 창 비율이 다르면 검은 여백 |
| 접근법 | **저해상도 렌더 타깃 + 상수 재보정** | 카메라 줌 방식은 도트 격자를 통일하지 못해 기각 |

기각한 대안 — **카메라 줌**: 내부 좌표를 크게 유지하고 카메라 줌으로 화면만 480×270처럼 보이게 하는 방식. 속도/좌표 재보정은 피할 수 있으나, 배경과 스프라이트가 여전히 서로 다른 배율로 그려져 **도트 격자가 통일되지 않으므로** 핵심 목표를 달성하지 못한다.

## 3. 핵심 원리

480×270 캔버스에서 도트를 통일하려면:

- **배경을 거의 1:1로 그린다** (576×324 → 480×270, 살짝 크롭). 배경 도트 = 가상 픽셀 1칸.
- **모든 스프라이트를 정수 배율로 맞춘다** (꼬꼬 1배, 보스 2~3배). 소스 픽셀 1칸 = 가상 픽셀 N칸(N=정수).

그러면 화면 전환과 무관하게 배경·캐릭터·보스의 도트가 같은 크기로 보인다. 이것이 통일감의 핵심이며, 나머지 작업(속도·여백·UI)은 작은 캔버스에 맞춘 보정일 뿐이다.

## 4. 변경 대상

### 4.1 렌더 타깃 — [src/main.js](../../../src/main.js)

```js
width: 480,
height: 270,
roundPixels: true,   // 오타(roundPixel) 수정 — 서브픽셀 떨림 제거
// pixelArt: true 유지, Scale.FIT + CENTER_BOTH 유지
```

`scale.width/height` 기준으로 잡힌 좌표(스폰 위치, 화면 경계, 중앙 정렬 등)는 전부 자동으로 480×270에 맞춰진다.

### 4.2 배경 1:1 매핑 — [src/backgrounds/Background.js](../../../src/backgrounds/Background.js)

현재 `scale = height/sourceHeight`(324→270, 0.83배 축소)를 거의 1:1로 변경한다. 576×324 원본이 480×270보다 크므로 가장자리가 살짝 크롭되지만, 패럴럭스 배경이라 무해하다. → 배경 도트 = 가상 픽셀 1칸.

### 4.3 스프라이트 표시 배율 (도트 통일의 핵심)

| 대상 | 현재 | 제안 시작값 | 근거 |
| --- | --- | --- | --- |
| 꼬꼬 [Player.js:41](../../../src/gameobjects/Player.js#L41) | `setScale(3)` | `1` | 48px → 270칸 중 18%, 적당 |
| 보스 [GoldPig.js:12](../../../src/gameobjects/monsters/GoldPig.js#L12) | `setScale(10)` | `3` (상수화) | base 배율을 상수로 빼서 복원(:403)·ultimate(5.5) 동기화 |
| 적 탄막 setScale(2~2.5) | 2~2.5 | `1~1.5` | 16px 탄을 화면에 맞게 |
| next-arrow [NormalScene.js:82](../../../src/scenes/NormalScene.js#L82) | `setScale(2)` | `1` | |

보스는 `BASE_SCALE` 상수 하나로 빼서 생성/복원/ultimate 배율이 한 값에서 파생되도록 정리한다.

### 4.4 월드 속도/오프셋 (게임 feel — 플레이테스트로 튜닝)

픽셀/초 속도와 절대 오프셋은 캔버스가 ~1/4로 작아졌으니 비례 축소한다. **시작 계수 ≈ 0.4**(레퍼런스 폭 ~1200 가정), 이후 플레이로 미세조정한다. 아래 값은 모두 **시작값**이다.

| 대상 | 현재 | 제안 시작값 |
| --- | --- | --- |
| 플레이어 speed [Player.js:22](../../../src/gameobjects/Player.js#L22) | 200 | ~80 |
| 알 속도 baseBulletSpeed | 400 | ~160 |
| 몬스터 속도 [NormalScene.js:17](../../../src/scenes/NormalScene.js#L17) | 200 (+5/s) | ~80 (+2/s) |
| 보스 탄/소환 속도 (GoldPig 300~500) | 300~500 | ~120~200 |
| 플레이어 시작 x [Player.js:36](../../../src/gameobjects/Player.js#L36) | 100 | ~30 |
| 하트 스폰 여백 [BaseScene.js:297](../../../src/scenes/BaseScene.js#L297) | 100 | ~30 |
| 보스 패턴 ±100/-100 오프셋 (GoldPig) | ±100 | ~÷4 (±25) |

### 4.5 HUD/UI — [src/scenes/HudScene.js](../../../src/scenes/HudScene.js)

HudScene도 480×270로 렌더되므로 폰트/아이콘이 거대해진다. 레이아웃은 `scale.width/height` 상대라 유지하고 크기만 축소한다.

- points/time `bitmapText` 24 → ~10
- effect 텍스트 fontSize 16 → ~8, 아이콘 iconTarget 24 → ~12
- life `setScale(1.5)` → 축소

⚠️ 일반 `add.text`는 작은 px에서 흐릿하다. 이는 **폰트 통일(리뷰 #2/#4)** 영역이라 이번 범위 밖이다. 이번엔 크기만 맞추고 후속 작업으로 남긴다.

## 5. 검증 방법

자동 테스트 스위트가 없으므로 **디버그 진입(`?scene=...`) + 스크린샷 + 실제 플레이**로 확인한다.

- 각 씬(menu / first / boss / GameOverScene / GameClearScene)을 띄워 **배경 도트 ≈ 캐릭터 도트**인지 육안 확인
- 실제 플레이로 속도감·보스 패턴이 화면 안에 들어오는지 확인하며 4.4 계수 튜닝
- 레터박스(검은 여백)가 16:9 아닌 창에서 의도대로 나오는지 확인

검증 진입 예: `http://localhost:5173/chicken-game/?scene=boss&items=max`

## 6. 단계별 롤아웃

1. **렌더 타깃 + 배경 1:1** → 5개 씬 스크린샷으로 도트 통일 1차 확인
2. **스프라이트 배율 재보정** (꼬꼬 / 보스 / 탄막 / 화살표)
3. **HUD/UI 크기 재보정**
4. **월드 속도/오프셋 재보정 + 플레이테스트 튜닝**

각 단계 끝에 스크린샷/플레이로 검증한 뒤 다음 단계로 넘어간다.

## 7. 리스크

- **게임 feel 변화**: 4.4의 속도/오프셋은 시작값이며 플레이테스트로 맞춰야 한다. 가장 불확실한 부분.
- **보스 패턴 지오메트리**: ±100 오프셋이 270칸 캔버스에서 화면을 벗어나지 않도록 보정 필요.
- **배경 크롭**: 576→480 폭 크롭으로 가장자리 일부가 잘림(패럴럭스라 허용 범위).
- **UI 텍스트 흐림**: 작은 px의 일반 `add.text`는 흐릴 수 있음 — 폰트 통일(후속)에서 해결.
