# PRD: 랭킹보드 (Leaderboard)

> 라벨: `ready-for-agent`

## Problem Statement

플레이어가 한 판(약 10분)을 끝내면 점수(`points`)를 GameClear / GameOver 화면에서 한 번 보고 끝이다. 다른 사람의 점수와 비교할 방법도, 자기 최고 기록을 남길 방법도 없어서 "한 번 더 해서 1등 해보자"는 동기가 생기지 않는다. 게임은 GitHub Pages에 정적으로 배포되어 있어, 서버 없이 어떻게 공유 랭킹을 유지할지가 핵심 제약이다.

## Solution

게임이 끝났을 때(클리어든 게임오버든) 그 판의 점수가 랭킹 상위권에 들면 이름을 입력받아 공유 랭킹보드에 등록한다. 랭킹보드(Top N)는 메인 메뉴와 게임 종료 화면 양쪽에서 볼 수 있다.

정적 배포는 그대로 유지한다. `dist`는 지금과 똑같이 GitHub Pages로 나가고, 브라우저가 **런타임에 Supabase로 직접 점수를 read/write** 한다. 별도 백엔드 서버 코드는 없다. Supabase 무료 티어 + 공개 anon 키 + Row-Level-Security(RLS) 정책으로 "누구나 등록 가능 / 상위 N개 공개 조회" 만 허용한다.

## User Stories

1. 플레이어로서, 게임을 클리어하면 내 점수가 랭킹에 들 만한지 즉시 알 수 있어서, 기록 도전 동기를 얻고 싶다.
2. 플레이어로서, 게임오버로 끝나도 그 판 점수가 상위권이면 랭킹에 등록할 수 있어서, 끝까지 못 깨도 점수 경쟁에 참여하고 싶다.
3. 플레이어로서, 점수가 랭킹 진입 조건을 넘으면 이름을 입력하는 창이 떠서, 보드에 내 이름을 남기고 싶다.
4. 플레이어로서, 이름 입력 시 글자 수 제한과 허용 문자가 명확해서, 깨지거나 거부되는 이름을 넣지 않고 싶다.
5. 플레이어로서, 이름을 비우거나 입력하지 않고 닫아도 게임 흐름이 막히지 않아서, 등록을 건너뛸 수 있다.
6. 플레이어로서, 점수가 랭킹 진입 조건에 못 미치면 이름 입력 없이 바로 랭킹보드를 볼 수 있어서, 내가 몇 위권인지 확인하고 싶다.
7. 플레이어로서, 등록 직후 랭킹보드에서 내 기록이 하이라이트되어 보여서, 내가 방금 몇 위에 올랐는지 확인하고 싶다.
8. 플레이어로서, 게임 종료 화면에서 랭킹보드를 본 뒤 메뉴로 돌아갈 수 있어서, 평소 흐름이 유지되길 바란다.
9. 플레이어로서, 메인 메뉴에서 "랭킹" 버튼을 눌러 언제든 랭킹보드를 볼 수 있어서, 플레이 전에 목표 점수를 확인하고 싶다.
10. 플레이어로서, 랭킹보드에 순위·이름·점수가 보여서, 상위 기록들을 한눈에 비교하고 싶다.
11. 플레이어로서, 클리어로 등록된 기록과 게임오버로 등록된 기록을 구분(예: 표식)할 수 있어서, 완주 기록을 알아보고 싶다. *(선택)*
12. 플레이어로서, 네트워크가 끊기거나 Supabase가 응답하지 않아도 게임이 멈추거나 깨지지 않아서, 오프라인에서도 게임 자체는 즐기고 싶다.
13. 플레이어로서, 랭킹 등록/조회가 실패하면 "랭킹을 불러올 수 없어요" 같은 안내를 보고서, 무슨 일이 일어났는지 알고 싶다.
14. 한국어 사용자로서, 랭킹보드의 모든 라벨(순위/이름/점수/제목/버튼)이 한국어로 보여서, 자연스럽게 읽고 싶다.
15. 영어 사용자로서, 같은 라벨이 영어로 보여서, EN 모드에서도 일관되게 쓰고 싶다.
16. 플레이어로서, 언어를 전환하면 열려 있는 랭킹보드의 라벨도 즉시 바뀌어서, 메뉴의 다른 텍스트와 동작이 같길 바란다.
17. 플레이어로서, 랭킹보드를 불러오는 동안 로딩 표시가 보여서, 멈춘 게 아니라 기다리는 중임을 알고 싶다.
18. 플레이어로서, 같은 점수가 여러 개면 일관된 기준(예: 먼저 등록한 기록이 위)으로 정렬돼서, 순위가 들쭉날쭉하지 않길 바란다.
19. 운영자로서, anon 키가 노출돼도 RLS가 등록/조회만 허용하고 삭제·수정은 막아서, 누군가 보드를 통째로 지우지 못하게 하고 싶다.
20. 운영자로서, Supabase 설정(테이블/정책 SQL)이 문서로 남아서, 환경을 다시 만들 때 그대로 재현하고 싶다.

## Implementation Decisions

### 백엔드: Supabase (정적 배포 유지)
- GitHub Pages 정적 배포는 변경 없음. 빌드 산출물(`dist`)은 지금과 동일하게 배포된다.
- 브라우저가 런타임에 Supabase REST/JS 클라이언트로 직접 점수를 등록/조회한다. 별도 서버 코드 없음.
- Supabase 접속 정보는 Vite 환경변수(`import.meta.env.VITE_*`)로 주입한다. anon 키와 URL은 클라이언트에 노출되는 공개 값이며, 보안은 RLS로 건다.
- 테이블 `leaderboard`: `id`, `name`, `score`, `cleared`(boolean), `created_at`. RLS 정책: **익명 INSERT 허용**, **SELECT 허용(상위 N개 조회)**, UPDATE/DELETE 차단. 정렬 기준은 `score DESC, created_at ASC`(동점 시 먼저 등록한 기록이 위 → User Story 18).
- 클라이언트만으로는 점수 위조가 가능하다는 점은 캐주얼 게임 수준에서 수용한다(Out of Scope의 anti-cheat 참고).

### `LeaderboardService` (깊은 모듈)
- Supabase 클라이언트를 감싸는 데이터 계층. 외부 인터페이스만 노출하고 REST/인증/에러 처리를 내부에 숨긴다.
- 인터페이스:
  - `getTopScores(limit)` → `Promise<Array<{ name, score, cleared, created_at }>>` (정렬된 상위 N개)
  - `submitScore({ name, score, cleared })` → `Promise<void>`
- 네트워크/서비스 실패 시 throw하거나 빈 배열 등 호출부가 게임 흐름을 막지 않도록 처리할 수 있는 형태로 반환(에러 처리 계약은 스펙 단계에서 확정).

### `qualifiesForLeaderboard(score, topScores, capacity)` (순수 함수)
- 이 점수가 이름 입력 프롬프트를 받을 자격이 있는지 판단하는 순수 함수.
- 규칙: 현재 보드가 `capacity` 미만이면 무조건 자격 있음. 가득 찼으면 `score`가 보드 최하위 점수보다 클 때 자격 있음. (동점 시 진입 여부는 스펙에서 확정 — 기본값: 동점은 진입 불가, 즉 "초과"만 인정.)
- `LeaderboardService`에서 분리된 별도 순수 모듈로 둬서 단위 테스트가 쉽게 한다.

### `NameEntryDialog` (재사용 UI)
- 점수가 자격을 넘으면 뜨는 이름 입력 오버레이. MenuScene의 다이얼로그(크림색 패널 + 골든 테두리 + 스크림) 스타일을 재사용한다.
- 이름 길이/허용 문자 제한(기본: 공백 제외 최대 길이 제한, 트림), 등록/건너뛰기 동작 제공. 빈 이름/취소 시 등록 없이 흐름 진행(User Story 5).
- HTML `<input>` 오버레이 또는 Phaser 기반 입력 중 택1 — 스펙 단계에서 확정(모바일 키보드/IME 고려).

### `LeaderboardPanel` (재사용 UI)
- 상위 N개 목록(순위·이름·점수, 클리어 표식은 선택)을 렌더링하는 재사용 뷰. MenuScene과 게임 종료 화면 양쪽에서 같은 컴포넌트를 쓴다.
- 로딩 상태, 조회 실패 안내, 방금 등록한 기록 하이라이트(종료 화면 진입 시)를 지원.
- i18n: `onLanguageChanged` 구독으로 언어 전환 시 라벨 즉시 갱신, `shutdown`에서 구독 해제(MenuScene 패턴 준수).

### 종료 화면 통합 (`GameClearScene` / `GameOverScene`)
- 두 씬 모두 `init(data)`에서 그 판의 `points`를 받는다(현재도 `end_points`로 보유).
- 종료 흐름: 점수 표시 → `getTopScores` 조회 → `qualifiesForLeaderboard`로 자격 판단 → 자격 있으면 `NameEntryDialog` → `submitScore` → `LeaderboardPanel`(내 기록 하이라이트). 자격 없으면 바로 `LeaderboardPanel`.
- GameClearScene의 엔딩 크레딧 스크롤 연출과의 순서/타이밍은 스펙에서 조정(크레딧 후 랭킹 표시 등).

### `MenuScene` 통합
- 기존 Play/Help 버튼과 같은 `Button` 컴포넌트로 "랭킹" 버튼 추가 → 클릭 시 `LeaderboardPanel` 표시.

### i18n
- 랭킹 관련 문자열(제목/순위/이름/점수/등록/건너뛰기/로딩/에러/클리어 표식)을 `src/i18n/locales/`의 KO/EN 양쪽에 추가하고 `t("key")`로 사용.

### 설정/문서
- Supabase 테이블 생성 + RLS 정책 SQL을 문서로 남긴다(재현용, User Story 20).
- `.env` 예시(`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`)와 GitHub Actions 빌드 시 환경변수 주입 방법을 문서화. (배포 워크플로 `.github/workflows/build.yml`에 빌드 시점 env 주입 필요 — 스펙에서 확정.)

## Testing Decisions

- **좋은 테스트의 기준**: 외부 동작(입력 → 출력/부수효과)만 검증하고 내부 구현 디테일은 검증하지 않는다. 모듈 인터페이스에 대고 테스트한다.
- **테스트 러너**: 현재 프로젝트엔 없으므로 **Vitest를 신규 도입**한다(`npm run test`). UI/Phaser 씬은 자동 테스트 대상에서 제외하고 브라우저 수동 검증으로 다룬다.
- **테스트 대상**:
  - `qualifiesForLeaderboard` — 순수 함수. 케이스: 보드가 빈/미만/가득참, 최하위보다 큰/같은/작은 점수, 경계값(capacity 정확히 채움), 동점 처리.
  - `LeaderboardService` — `fetch`(또는 Supabase 클라이언트)를 모킹해 `getTopScores`가 정렬/limit를 올바르게 요청·반환하는지, `submitScore`가 올바른 페이로드를 보내는지, 실패 응답에서 계약대로 동작하는지 검증.
- **Prior art**: 현재 코드베이스에 테스트 선례 없음(첫 도입). 두 모듈 모두 Phaser/DOM 의존이 없도록 분리해 순수 단위 테스트가 가능하게 설계한다.

## Out of Scope

- **Anti-cheat / 점수 위조 방지**: 클라이언트 전용 구조라 점수 위조가 가능. 서명·검증·서버 사이드 검산은 이번 범위 밖(캐주얼 게임 수준에서 수용).
- **인증/로그인**: 로그인 없이 익명 이름 입력만. 사용자 계정, 본인 기록 관리, 중복 이름 처리(동명이인 허용)는 범위 밖.
- **욕설/부적절 이름 필터링**: 기본 길이/문자 제한만. 콘텐츠 모더레이션은 범위 밖.
- **랭킹 페이징/검색/필터**: 상위 N개 단순 조회만. 전체 목록 스크롤·기간별·국가별 필터는 범위 밖.
- **백엔드 마이그레이션 추상화**: Supabase 외 다른 백엔드로 손쉽게 바꾸는 추상 레이어는 만들지 않는다(`LeaderboardService` 인터페이스 분리로 충분).
- **오프라인 큐잉**: 네트워크 실패 시 점수를 로컬에 쌓아 나중에 재전송하는 기능은 범위 밖(실패 시 안내만).

## Further Notes

- 정적 배포 유지가 최우선 제약이었고, Supabase 클라이언트 직접 호출로 이를 만족한다(서버리스, Pages 워크플로 그대로).
- `points`는 이미 씬 간 전달되고 종료 화면에 도달하므로, 추가 점수 집계 로직 없이 종료 시점 값을 그대로 등록한다.
- Top N의 N(보드 capacity), 이름 최대 길이, 동점 진입 규칙 등 수치 파라미터는 스펙 단계(`/dev-spec`)에서 확정한다. 기본 제안: Top 10, 이름 8자.
- 다음 단계: 이 PRD를 기반으로 `/dev-architecture` → `/dev-spec` → `/dev-testcase` 진행 가능.
